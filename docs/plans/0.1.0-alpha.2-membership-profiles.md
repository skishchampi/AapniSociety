# 0.1.0-alpha.2 — Cooperative Membership and Profiles

Date: 2026-08-24
Status: In progress

Frame note: this repo follows the roadmap numbering. Alpha.2 is Cooperative
Membership and Profiles. Introductions stay in alpha.3. The old handoff line
that called introductions "alpha.2" was a conflation and is corrected here.

## Existing artifacts (alpha.1 carry-over)

- `ServiceCategory`, `WorkerProfile`, `HouseholdProfile` models exist.
- Worker categories, languages, served localities, availability, rate floor,
  and contact visibility already have fields.
- `/api/v1/me/worker-profile/` and `/api/v1/me/household-profile/` give both
  roles a full GET/PUT onboarding surface.
- Gaps: no cooperative approval workflow, no service-need record, no explicit
  privacy-exposure tests.

## New in this gate

1. `MembershipRequest` model. Fields: user, role_sought, status
   pending/approved/rejected, reviewed_by, reviewed_at, rejection_reason.
   One pending request per user, enforced by a partial unique constraint.
   Approval sets `user.primary_role` to the sought role.
2. Membership API under `/api/v1/membership/`:
   - `POST request/` — any signed-in user asks to join as worker or household.
   - `GET requests/mine/` — the caller sees own requests.
   - `GET queue/` — moderators, operators, admins only.
   - `POST requests/{id}/review/` — approve or reject, with reason on reject.
3. `ServiceNeed` model. Fields: household, category, title, details, locality,
   status open/matched/closed. Owner-scoped CRUD at `/api/v1/needs/`.
   Moderators see all needs. There is no public endpoint, ever.
4. Privacy tests. Profile responses expose no phone or email. One household
   never reads another household's need. Workers cannot create needs.

## Roadmap acceptance mapping

| Criterion | Where it lands |
|---|---|
| Worker can create a complete profile | existing PUT endpoint plus tests |
| Household can create a service-need request | `ServiceNeed` CRUD |
| Moderator can approve or reject membership | membership review endpoints |
| Private fields stay out of normal APIs | serializer exposure tests |

## Out of scope in this gate

Service offers and matching (alpha.3+), introductions (alpha.3), SMS gateway,
httponly-cookie hardening, idempotency keys.
