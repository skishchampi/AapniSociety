# 0.1.0-alpha.3 — Introductions

Date: 2026-08-24
Status: Planned, not started

Frame: consent-gated, mediator-routed trust transfer. No public ratings and no
public directories, ever. A household asks; the cooperative routes; the worker
decides. Contact details stay hidden until the worker reveals them with an
explicit action.

## Models (backend/apps/members)

1. `IntroductionRequest`
   - `household` FK HouseholdProfile, `worker` FK WorkerProfile
   - `category` FK ServiceCategory, nullable
   - `note` TextField — what the household is asking for
   - `status`: requested → routed → accepted | declined | withdrawn
   - `routed_by` FK moderator user, null until routed
   - timestamps
2. `IntroductionEvent`
   - `introduction` FK, `actor` FK user, `what` CharField (one of a fixed verb
     set: requested, routed, accepted, declined, withdrawn, contact_revealed)
   - `detail` TextField blank
   - created_at. Append-only: no updates, no deletes.
3. Contact reveal stays event-based, not a stored flag: a `contact_revealed`
   event on the introduction authorizes the reveal endpoint for that pair.

## API surface

- `POST /api/v1/introductions/` — household files a request naming a worker.
- `GET /api/v1/introductions/mine/` — role-scoped: households see their own,
  workers see requests addressed to them, moderators see all.
- `POST /api/v1/moderation/introductions/{id}/route/` — moderator moves a
  requested introduction to routed. Moderators only.
- `POST /api/v1/introductions/{id}/accept/` and `/decline/` — worker decides.
- `POST /api/v1/introductions/{id}/reveal-contact/` — worker-only. Allowed only
  after accept. Writes the contact_revealed event and returns contact fields
  once for that call.
- `GET /api/v1/introductions/{id}/events/` — participants plus moderators;
  auditable history.

## Privacy rules (hard)

- No serializer ever includes phone or email outside the reveal response.
- Decline reasons are visible to the moderator, never to the household.
- The household sees worker identity only after routing; contact only after
  reveal. The worker sees the household only after routing.

## Tests to write

- Full lifecycle: request → route → accept → reveal, events recorded in order.
- Worker decline stores nothing about reasons toward the household.
- Reveal before accept returns 409. Reveal by non-worker returns 403.
- Serializer sweep: no phone/email anywhere except the reveal response.
- Role scoping: strangers get 404s, not 403s, on other people's introductions.

## Out of scope in this gate

Notification delivery (hooks only), references and bargaining (alpha.4),
safety reports (alpha.5).
