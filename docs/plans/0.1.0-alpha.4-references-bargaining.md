# 0.1.0-alpha.4 — References and Bargaining

Date: 2026-08-24
Status: Planned, not started

Frame: worker reputation is portable and private. There is no public ratings
marketplace, no public worker profile browsing, and no aggregate leaderboards.
A reference exists because a completed introduction created real work.

## Models (backend/apps/members)

1. `WorkerReference`
   - `introduction` OneToOneLink to IntroductionRequest — a reference can only
     exist for an accepted introduction. This reuses the audit trail instead of
     inventing a second source of truth for "did the work happen".
   - `written_by` FK household user, `worker` FK WorkerProfile (denormalized
     from the introduction for query speed)
   - `body` TextField, `rating` small int nullable — kept optional and private;
     the design centres written references, not star scores
   - `visibility`: private / coop / shared — default private
   - timestamps
2. `ReferenceRequest`
   - `worker`, `household`, `introduction` nullable (a request may precede a
     new engagement), `status`: pending → written | declined | expired
3. Rate floor support on `ServiceNeed`:
   - `offered_rate` decimal nullable on the need
   - computed property `below_floor` comparing offered rate to the matched
     worker's `default_rate_floor`

## API surface

- `POST /api/v1/reference-requests/` — worker invites a household to write.
- `POST /api/v1/references/` — household writes a reference for an accepted
  introduction.
- `GET /api/v1/me/references/` — the worker's own references with visibility.
- `PATCH /api/v1/references/{id}/visibility/` — worker-only control.
- Shared references appear in the worker's introduction payload only after
  routing, so bargaining context arrives without public browsing.
- Admin view: aggregate rates and demand counts per category/locality —
  cooperative-side economics only, never exposed to households.

## Privacy rules (hard)

- Households cannot browse workers or ratings. Discovery stays mediated
  through introductions.
- A reference is visible to non-participants only when the worker sets
  visibility to shared, and then only inside routed introductions.
- Below-floor flags go to the worker and moderators, never to the household.

## Tests to write

- Reference creation requires an accepted introduction (409 otherwise).
- Visibility switch: private reference invisible in every payload but the
  owner's; shared appears post-routing.
- Household listing endpoints return no rating aggregates (sweep test).
- Below-floor flag computes only against the worker's floor and shows to
  worker + moderator roles.

## Out of scope in this gate

Public search or profiles, payments/dispute flow, safety reports (alpha.5).
