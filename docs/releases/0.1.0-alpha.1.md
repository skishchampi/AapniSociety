# Release 0.1.0-alpha.1 — Foundations

Date: 2026-06-24
Branch: `reboot-13years-later`

First modern implementation scaffold for the AapniSociety rebuild: a Django 5 + DRF
backend and a React + TypeScript Vite PWA, in a monorepo, with a local docker-compose
stack and CI. Per the [implementation plan](../plans/0.1.0-alpha.1-foundations.md); product
scope is fixed by the [roadmap](../aapnisociety-roadmap.md) and [SRS](../aapnisociety-srs-formal.md).

## Acceptance (roadmap §5)

| Criterion | Met by |
|---|---|
| Worker and household users can sign in locally | Phone OTP request/verify (`/api/v1/auth/otp/`) → JWT access + rotating refresh; frontend SignIn → Onboarding creates the matching worker/household profile; `/me/` returns role |
| Admin can view users and profiles | Django `/admin/` with `User`, `WorkerProfile`, `HouseholdProfile`, and geo models registered; superuser via `createsuperuser` |
| Test suite runs via one command | `make test` → backend `pytest` (10 tests) + frontend `vitest`; `.github/workflows/ci.yml` runs both plus a secret scan on push/PR |

## Deliverables

- Backend modular monolith: `accounts` (custom phone User, OTP, JWT, AuditEvent), `geo`
  (City/Locality/Building/Unit), `members` (ServiceCategory, WorkerProfile, HouseholdProfile).
- Dev OTP flow (no SMS gateway; code returned/logged only when `DEBUG`).
- Frontend PWA: SignIn / Onboarding / Dashboard, typed API client with refresh-on-401,
  installable service worker + manifest.
- `infra/` docker-compose stack (PostGIS, redis, backend, frontend) + Dockerfiles + `.env.example`.
- CI: ruff + pytest (against Postgres), eslint + vitest + vite build, gitleaks secret scan.

## Security / correctness hardening in this release

- **OTP brute-force backstop:** per-phone issuance cap over a window (so the per-challenge
  attempt cap cannot be reset by re-requesting); separate IP throttle scopes for issue vs verify.
- **JWT key floor:** HS256 signs over a `SECRET_KEY` of ≥ 32 bytes (RFC 7518 §3.2); `prod`
  settings refuse to boot on the dev placeholder or a short key.
- **Refresh rotation fix:** the SPA now persists the rotated refresh token returned on refresh,
  so sessions survive past the first access-token expiry.
- **Role privilege guard:** clients can self-assign only `worker`/`household`; privileged roles
  come from admin/management commands only (regression-tested).

## Privacy guardrails (SRS §6.1)

No caste, religion, marital-status, or relationship fields exist anywhere in the schema. This is
a hard schema rule, enforced from the first migration.

## Not in this gate

Per plan §6: no introductions, references, rate bargaining, safety notes, moderation, payments,
public search, native apps, SMS gateway, or algorithmic matching. Those begin at alpha.2+.
