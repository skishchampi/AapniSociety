# AapniSociety 0.1.0-alpha.2 Release Notes

Date: 2026-08-24
Status: Complete

## Release Goal

`0.1.0-alpha.2 - Cooperative Membership and Profiles` makes worker and
household records usable for a real pilot: complete profiles, cooperative
approval of membership, and household-posted service needs.

## What Changed

- Membership approval workflow: users ask to join as worker or household;
  moderators review a pending queue and approve or reject with a reason.
  Approval flips the requester's primary role. One pending request per user,
  enforced by a partial unique constraint.
- Service needs: households post needs against a category. Lists are
  owner-scoped; moderators see all. There is no public endpoint.
- Profile editors for both roles. Workers set display name, languages, work
  categories, served localities, weekly availability windows, and a monthly
  rate floor. Households set their name and cooperative visibility.
- Moderator review page in the PWA, plus membership, needs, and profile pages.
- Profile saves use PATCH instead of PUT, so partial saves stop resetting
  unmentioned fields.
- Privacy tests: profile responses carry no phone or email; one household
  never reads another household's need; workers cannot post needs.
- Legacy archive hygiene: absolute home paths genericized and two stale bin
  build outputs untracked from the 2012 Android tree.
