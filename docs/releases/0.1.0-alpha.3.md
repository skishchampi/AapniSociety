# AapniSociety 0.1.0-alpha.3 Release Notes

Date: 2026-08-24
Status: Complete

## Release Goal

`0.1.0-alpha.3 - Introductions` implements consent-gated, mediator-routed
introductions with an auditable history. A household asks; the cooperative
routes; the worker decides; contact details appear only when the worker
reveals them.

## What Changed

- `IntroductionRequest` model with the flow requested → routed →
  accepted | declined | withdrawn, plus moderator and timestamp records.
- `IntroductionEvent`: an append-only audit line written at every transition.
  Django admin treats both models as read-only.
- API: households file requests naming a worker; lists are role-scoped;
  moderators route at `/api/v1/moderation/introductions/{id}/route/`; the
  addressed worker accepts or declines; households can withdraw while open.
- Contact reveal: worker-only, allowed only after acceptance. It writes its
  own `contact_revealed` event and returns phone and email in that single
  response. Every other serializer stays free of contact fields.
- Identity gating: counterpart names become visible only after routing.
  Decline reasons never reach the household. Strangers get 404s, not 403s.
- Notification hook: every transition funnels through one function in
  apps/members/notifications.py, ready for a delivery channel later.
- Frontend: one role-aware page at `/introductions` covering filing,
  moderation routing, worker accept/decline, contact reveal, and an
  expandable events trail per request. Dashboard gains the link.
- Profile saves across the app use PATCH (landed with this gate's frontend).
